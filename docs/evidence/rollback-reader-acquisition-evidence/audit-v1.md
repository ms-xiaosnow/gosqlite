# Reader-acquisition test behavior audit

The new `internal/pager/reader_acquisition_test.go` reads only Go source in its AST test. It requires immediate native ownership adoption, initial regular-file rejection, successful SHARED before metadata reassignment, error propagation, and the refreshed info flowing into Reader/header parsing, followed by unchanged stability checking. It invokes no native backend in the source regression or the pure-memory BUSY-classification law.

The ordinary regression uses `createEmpty` from `tx_test.go`: fresh temporary path, normal OpenTx(Create), Commit and Close. A single writer performs 128 normal schema-cookie commits and 32 intentional normal rollbacks; two independent readers repeatedly open, read, yield, read the same pinned page again and close. All pages remain valid ordinary SQLite pages; no file bytes are written by test code. The final ordinary open checks generation 128. A cooperative 20-second wall deadline bounds retries without interrupting a native call. Worker result channels are bounded; workers join after normal Reader close before the test returns. BUSY is accepted only if all unwrapped leaves are pager/VFS BUSY; joined unknown, ownership, cleanup and ErrChanged diagnostics fail.

Selected existing tests reviewed: TestTxCreatePageSizesAndReadSnapshot creates/reads valid pages at three supported sizes, changes only returned in-memory read copies and closes normally. TestReadOnlyPageAccess reads intact fixed fixtures, mutates only caller-owned copies, exercises invalid logical page requests, and verifies fixture hash unchanged. TestTransactionDeferredSnapshotTiming performs ordinary SQL commits, logical savepoints/rollback, snapshot pinning and cooperating BUSY with normal Rows/Tx close. No namespace replacement or fault injection is present in these selected tests/helpers.

Restrictions: no broad prior baseline/full suite; no manual tags, physical corruption/tamper/wrong-key/missing-selected-file, namespace mutation, process kill/crash/hot recovery, injected native I/O/lock/unmap/close/Sync/shortwrite/disk-full/permission failure, or interrupted publication/rekey. Scope guard runs before all selected database execution. The source-order failure on an unfixed control is source parsing only, never an injected native race.

The frozen V2 harness's main.go, workload.go and report_test.go were read before composition/execution. Its sole writer updates real account rows and generation atomically, models accepted commit ordinals, exercises full rollback/savepoint histories, and each reader checks every exact row twice in a pinned snapshot. It uses ordinary SQL, normal close/reopen, in-process cooperative context cancellation and bounded resource accounting. The command's os.Exit occurs only after run has joined workers and attempted normal closure. No tests from the old broad baseline or physical failure workflows will run. Harness files remain byte/mode-identical to the provided V2 patch. Only rollback profile is selected for the fixed-duration command trials.
