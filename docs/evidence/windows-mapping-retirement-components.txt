Correction
----------
The private mappingRetirement state machine is used by nativeUnmap and by
nativeMap's rejected-view cleanup through nativeUnmap. It records the first
unknown-close cause once, retaining handle/base/length, and returns that cause
on every later attempt without invoking either native operation. The native
adapter poisons its File. Strong File/maps/native.retained ownership keeps the
record and protecting resources reachable; it offers no reset or reclamation.
Object-close-before-view-unmap ordering remains unchanged, preserving live Bytes
after failed close. A known successful object close is never repeated when only
the represented view remains to retire. No lock interval, granularity, identity,
namespace or sharing algorithm was changed. This does not implement the separate
failed-OpenSharedSession pending-retirement group.
