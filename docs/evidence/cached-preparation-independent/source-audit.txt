Independent source and selected-test behavioral audit

Production scope: private DB preparation pointer; private Tx schemaChanged flag; pure shared INSERT/UPDATE/DELETE preparation extracted from existing row routines; buildWriteCatalog pure declaration validation extracted from existing write catalog; optional preparation cache population in user-table Query and Schema; invalidation at admitted Tx cookie, DDL rollback, savepoint schema rollback and Close. Public Options and Result field layouts remain unchanged.

Authority: execStatementLocked still checks Tx state, read-only and active transaction Rows, then attempts ensureSnapshotLocked. cachedPreparationFailureLocked is reached only on first-snapshot failure; it accepts only pure ordinary BUSY error trees and only supported DML with retained ordinary metadata. It never performs data reads/writes, evaluates expressions, promotes a writer, obtains a storage handle or publishes a successful Result. Successful admission always re-validates complete current catalog and ownership before executing. A stale cache cannot make an unsupported current view/extension schema writable.

Preparation sharing: both normal mutation and cached error classification call writeTable.prepareInsert/prepareUpdate/prepareDelete, including common table/column/rowid target and function validation, count checks and TRUE/FALSE shadowing. Syntax and argument conversion/binding precede DB admission. AST mutation is local to the newly parsed statement; immutable cached table metadata is read-only. Runtime constraint, type and expression errors are not evaluated before BUSY.

Error precedence: read-only, closed, expired Tx and active transaction Rows retain admission priority. onlyBusy recursively rejects every non-BUSY leaf, including context, poison or ownership errors. Existing non-BUSY admission errors are returned without cache interpretation. Pure error-tree tests never invoke a failing native operation. Cancellation checks exist during shared expression traversal and cache creation; cancellation from a parameter Valuer and pre-cancellation are tested warm/cold and preserve counters.

Memory: cache holds independent table name strings, folded keys, column name strings and IPK ordinal; roots are zero, defaults/types/index/extension objects absent. Maximum retained charged metadata is min(MaxSortBytes,16MiB), separate from active sort memory. A fixed 256-byte empty-catalog charge originally escaped the loop guard; independent TestReviewPreparationEmptyQuota reproduced limits 1/64/255 retaining 256, and owner fixed both entry guards before v3. Read-side declaration parsing is precharged with a 128x SQL-byte allowance. Whole catalog/table count and parser limits already bound inputs. Published cache maps/columns are replaced, never mutated; Close clears the pointer.

Rollback: automatic DDL commit-BUSY rolls back and clears uncommitted cache; successful local CREATE updates copied metadata; full DDL rollback and rollback-to that changes the schema cookie clear it; data-only savepoint rollback retains it. Parent/full rollback after any schema-changing statement conservatively clears it. Stale metadata while a peer holds EXCLUSIVE remains diagnostic only; next successful snapshot refreshes normal execution.

Selected tests and helpers read: sqlite/preparation_cache_test.go, connection_counters_test.go, connection_counters_internal_test.go, transaction_control_review_test.go (only helpers), independent native tests; driver/connection_counters_test.go, preparation_cache_test.go, writableDatabase/mustExec/checkAffected helpers and independent test; internal/sql/connection_test.go; internal/testkit/connection_counters_conformance_test.go, preparation_cache_conformance_test.go, readonly_conformance_test.go (only oracle/native comparison helpers), independent oracle tests. Databases are created and changed through intact ordinary native/official SQL; locks are cooperative BEGIN/normal rollback/commit, quotas and contexts are ordinary logical rejection. Unsafe.StringData only compares pointers from valid Go strings, never mutates storage. CLI start is synchronized with .print (does not read schema), and every process finishes via EOF/.quit and Wait. No broad suite, manual build tags, restricted physical/namespace/failure/crash/recovery action is selected or performed.

Pinned public SQLite reference inspected: src/prepare.c sqlite3ReadSchema/sqlite3Init/schemaIsValid; src/vdbe.c OP_Transaction schema-cookie checks/changeCntOn; src/main.c sqlite3RollbackAll schema reset. Typed observed behavior is authoritative for the tested profile. Full stale-schema reprepare, session/extension caches, constant-SELECT cache warm-up and full SQLite preparation equivalence remain explicitly outside this implementation.
