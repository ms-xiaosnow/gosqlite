Source findings
1. Admission and ownership transfer
   The public sqlite.OpenContext reserves a successful-close slot before
   canonicalOpenPath. Direct pager.OpenSharedSession also reserves before path
   resolution/acquisition. Exactly 1024 in-flight/live/pending-close reservations
   are allowed, with ErrLimit mapped to public ErrMemoryLimit/CodeNoMem on
   exhaustion. SharedCloseAdmission.take/Cancel serialize consumption; early
   validation/cancellation and unsuccessful opens abandon the unused close slot.
   The distinct 64 failed-open reservation remains before pager acquisition;
   successful opening transfers its owners and frees only that failed-open slot.
   Unsuccessful opening retains pending ownership in the existing failed-open
   registry while abandoning the unused successful-close slot. Public Windows
   canonicalization metadata remains under its separate bounded managed owner;
   the new reservation does not claim a new pre-pager metadata retry route.

2. Logical Close versus physical/managed retirement
   DB.Close marks SQL closure, invalidates Rows, joins their release diagnostics,
   and rolls back the transaction once. Subsequent shared-WAL Close calls reach
   session retirement without repeating those operations. SharedSession closes
   logically before group retirement, detaches its primary resource fields, and
   routes retries straight to the group. Direct pager Close with an active lease
   remains BUSY and leaves the session usable. The first lease-free Close makes
   at most one checkpoint attempt; KeepWALOnClose and existing causes/poison skip
   it. An unpoisoned reader-limited BUSY keeps the existing benign-close policy.
   The small private callback only factors this policy for memory laws; the
   production caller always supplies the real checkpoint and introduces no
   replaceable native-I/O hook.

3. Child-before-protector retirement and explicit completion
   First-close causes are passed through VFS CleanupOwners and adopted before
   retiring primary resources. Existing dependency collection merges all child
   edges for repeated File identities and fails closed on inconsistent cycles.
   Retirement proceeds nested obligations, index/views/mapping objects/DMS,
   WAL, then main. A retained child stops retirement before its protectors. Both
   pre-call and post-call status use explicit RetirementComplete, independently
   of the diagnostic error. A nil error with retained state is pending/poisoned;
   a completed owner with an error permits later stages and frees its slot when
   all owners are done. The index now clears its maps/File when the managed File
   has conclusively relinquished ownership even if its close returned a diagnostic.

4. Exact managed retries and platform boundaries
   The group stores only the three managed adapters and dependency owners. It
   neither extracts raw numbers nor calls an OS close directly. Common File.Close
   still retains mappings before descriptor/DMS release. Linux's consumed
   os.File.Close clears managed ownership and is never called again by this
   group. Pinned Go internal/poll FD.destroy sets Sysfd=-1 after the close result;
   no inference about a safe second native close is introduced.
   Windows file closeUnknown, mappingRetirement.closeUnknown, and metadata
   tombstones remain terminal. Represented view-only retirement can retry its
   actual managed view; uncertain raw-handle close cannot. Darwin retains its
   process-inode coordination: File retirement may transfer an idle descriptor
   to that existing owner, while uncertain close records stay attempted and are
   never physically closed again. The new successful-close registry does not
   claim that all process-wide deferred Darwin physical closes have happened.

5. Dropped errors, lock independence, and finite retained history
   Admission roots the group before successful opening returns, so discarding
   a database/sql connection or its Close error cannot lose ownership. Pending
   tokens are published atomically; snapshots hold the registry mutex only for
   enumeration and never take a group/native lock. Group operations occur after
   releasing the registry mutex. No registry-to-group lock inversion was found.
   Retained fields have no DB/session/Options/Rows/Tx/cache reference or callback
   to such objects. Managed native objects retain only their existing ownership
   bookkeeping. No finalizer, background retry, eviction, pathname lookup, or
   cleanup of unrelated groups was added.
   The group retains its first cause plus one replaceable current immutable
   pending token, not an accumulating chain of retry results. First-error VFS
   wrappers may still name already-retired Go File bookkeeping; explicit status
   skips it, and release clears the group's cause and owner fields. Caller-held
   historical error values can retain their own fixed graphs. Existing Darwin
   first-poison storage and Windows terminal mappings likewise do not accumulate
   retry histories. This is a structural bound, not a universal byte limit.

6. Public retry/discovery contract
   Wrapped/joined errors are completely discovered before any cleanup. Each
   distinct group is attempted once per call; completed groups cannot hide
   later pending groups. Tokens are immutable discovery leaves. Deep and wide
   exact 4096-node inputs are accepted; excessive/cyclic inputs return the
   explicit limit without resource effects or wrapping unsafe input. Snapshot
   slices are separate allocations; stale tokens remain harmless after cleanup.
   Pending errors preserve original causes and ErrPoisoned/CodeIOErr. Completed
   retries can still return diagnostics without ErrCloseCleanupPending; error
   presence alone is not ownership status. Nil/no-token input is only a no-op.
   Documentation accurately notes that additional public/application wrappers
   can push a full joined snapshot beyond the discovery limit, requiring batches.

7. Connector context decision
   Pinned Go 1.27.2 src/database/sql/driver/driver.go describes Connector context
   as dialing-only. Its synchronous DB.conn path accepts successful Connect
   without a second context check. The old post-success context branch dropped
   both db.Close's error and the connection. Removing it returns the successfully
   acquired connection while retaining pre-open and OpenContext cancellation
   checks. It does not authorize executing canceled queries. The standard
   library's finalClose/putConn paths can discard Close results and nil ci;
   the independent strong group plus snapshot supplies the missing retry route.

8. Scope and documentation
   New guarantees are limited to successful native plaintext WALShared sessions.
   The docs accurately distinguish actual remaining rollback Reader/Tx,
   WALExclusive, encrypted Store/session, other constructor/lease, and pre-pager
   metadata cleanup gaps from unexecuted qualification. The failed-open document
   has a dated superseding link while preserving historical evidence. Two
   documentation precision suggestions were incorporated before this freeze:
   full snapshot batching and limiting the no-raw-handle statement to the new
   group rather than all native backends. No production correction was requested.
