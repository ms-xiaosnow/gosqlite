Finding 1: constant IN-list error suppression (fixed)
---------------------------------------------------
SELECT 1 IN (1,2,abs(-9223372036854775808)) returned 1 natively, whereas
the pinned oracle raises integer overflow. NOT IN returned 0 rather than
raising; a searched CASE using the same IN condition also suppressed the error.
SQLite chooses a fully evaluated constant RHS for more than two entries, while
two-item/dynamic lists can short-circuit. The owner added bounded streaming
constant classification, retained-match evaluation and RHS error precedence,
including parameter and constant-alias treatment. No RHS set was allocated.
Independent TestExpressionReviewConstantInErrors now passes and also preserves
the two-item short-circuit and unselected CASE-arm cases. The owner's tests
add dynamic columns, function overrides, parameters, alias shadowing and RHS
versus lhs error priority. Pre-fix reproduction: ../expression-review-second.txt.

Finding 2: typeless physical-column alias representation collision (fixed)
------------------------------------------------------------------------
For e(id INTEGER PRIMARY KEY,x,h HALFVEC(3)), with physical x containing valid
dense text '[3,0,-4]', this query incorrectly acquired the alias's HALF identity:
SELECT CASE WHEN 1 THEN h END AS x FROM e WHERE vector_dims(x)=3.
The value resolver chose physical x, but DeclaredType treated its empty
declaration as failed lookup and fell back to the result alias. CAST-wrapped
aliases and nested ORDER BY reproduced the same error. This is an existing
alias-metadata integration defect exposed by the new expression trees.
The owner now checks successful physical-slot resolution independently of the
returned declaration string. TestExpressionReviewPhysicalUntypedAliasIdentity
passes all three reproductions. Independent representation-family tests also
cover alias identity for GSV/GSH/GSB/GSS and rejection of mixed CASE aliases.
Pre-fix reproduction: ../expression-review-second.txt.

Finding 3: CAST typename keyword classification (fixed)
------------------------------------------------------
The initial code rejected valid unquoted STRICT, WINDOW, OVER and FILTER
typenames. It also accepted seven invalid unquoted names: ADD, DEFERRABLE,
ISNULL, NATURAL, NOTHING, NOTNULL, TO. Each was verified against the pinned
official parser. A complete 151-name acceptance matrix established the exact
remaining deltas. The owner replaced reliance on the broader query reserved()
set with the pinned CAST-specific no-ID-fallback set. General query grammar is
unchanged. Quoted versions remain legal identifiers.
TestExpressionReviewCastContextualTypenames and
TestExpressionReviewOracleCastKeywordGrammar now pass.
Pre-fix evidence: ../expression-review-cast.txt and
../expression-review-keywords.txt.
