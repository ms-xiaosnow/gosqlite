Finding and correction

The initial materializeANNVector decoded typed query input before scratch
admission, then charged sparse input using canonical NNZ. Explicit zero entries
in legal sparse TEXT disappeared from query and exact-source rescore work.
Native sparseSearch correctly precharged original query entries, but its ANN
candidate rescoring still used canonical support counts. SQL ANN also lost the
initial raw-input entry charge. Existing exact sparse paths correctly counted
these input entries and rejected excessive scratch.

- Indexed SQL returned one row, method=hnsw, VectorRankNonzeros=0,
  ANNWork.ComponentWork=0, no error.
- Same query with NOT INDEXED returned ErrMemoryLimit.

The owner added annQueryPreflight before SQL query decoding, with lazy exact
fallback for inadmissible/invalid inputs; retained original sparse query entry
counts; and added annRescoreWork using original source TEXT entry counts.
Both work and scratch admission now precede candidate decoding. Graph metric
ANNWork still correctly counts actual canonical NNZ support, independently of
conservative source/parser work. The reviewer requested and verified the final
admission ordering as well as the first query-preflight fix.

Independent reproduction after correction: both indexed and NOT INDEXED queries
reject with ErrMemoryLimit. TestTypedANNSparseInputZeroEntryBudgets additionally

Resources, transactions and ownership
------------------------------------
Config and query quotas use bounded arithmetic; dimensions/support/list/sample
caps bound every multiplication. Numeric component, packed-byte and sparse
support units stay separate. Limits include spent widening and abandoned ANN
attempts before exact fallback. Exhaustion/cancellation produces an error and
no successful partial native result; SQL consumers must check Rows.Err.

Graph/list/query/result bookkeeping and source decode/identity scratch are
jointly admitted. Typed node/sample/centroid fixed allowances cover the larger
Value union; legacy exported dense formulas remain unchanged. The shared SQLite
adapter can conservatively reject tight old budgets earlier; documentation
explicitly distinguishes logical admission from RSS and broad SQL/pager work.

Source rows and graph/list/catalog updates share the existing storage.Statement
undo path, savepoints and transactions. Reindex builds in that same atomic scope.
Ordinary mutation/savepoint/rollback/rebuild/reopen tests pass for every supported
typed method. Shared-WAL snapshot tests keep prior graph/source generation while
a peer writes/reindexes; normal writer BUSY and subsequent rollback/write pass.

annStore owns snapshot-bound roots and no cross-query mutable graph cache. Query
candidate results retain immutable values or copied row data. Graph caches do
not escape SearchValue; SQL heap values retain appropriate row backing costs.
Rows.close clears sorted/current/query/parameter references, closes source,
releases the snapshot, removes DB tracking and decrements transaction activeRows.
