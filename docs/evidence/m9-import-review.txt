Seventeen named independent regressions cover:
- Exact signed int64 extrema, NULLs, signed binary32 zero, subnormals, extrema,
  and decimal binary32 double-rounding traps; an independent framed encoder
  checks both reported SHA-256 values against explicit expected component bits.
- Duplicate current-batch rollback and normal unchanged resume failure: data,
  accepted provenance, rejections, batch sequence and cursor remain atomic.
- Quarantine across deliberate committed-boundary pause/normal close/reopen;
  duplicate keys within/across batches, invalid PK and binary32 underflow.
- Source SHA-256 preflight and pre-canceled apply create no destination;
  manifest identity changes cannot resume; existing destinations require resume.
- An unrelated, intact native SQLite database remains byte-identical after
  rejecting both new import and resume. No namespace changes are exercised.
- CSV multiline/CRLF offsets, final record without newline, NULL, and a
  SQL-looking text value retained exactly through bound parameters.
- Missing/extra/duplicate NDJSON fields remain fatal schema errors even under
  quarantine, with no current-batch publication or fabricated rejections.
- Expected-row-count mismatch stays incomplete; empty NDJSON, header-only CSV,
  and all-rejected inputs preserve their distinct normal completion states.
- Real persisted HNSW and trained IVF indexes are used by native approximate
  searches after normal reopen. Cosine zero and insufficient IVF training rows
  retain all data in data_complete_index_pending, including repeated normal
  resume. Successful first-index progress survives a second-index blocker.
- Unordered dry-run stops at the explicit 65,536 unique-key budget; ascending
  65,537-row dry-run succeeds without destination creation.
- A bounded raw record whose decoded data exceeds the batch-byte cap fails as
  a resource error, not quarantine. Byte-bounded carry retains the exact last
  committed record offset and imports the deferred record once after resume.
- Pure-memory malformed manifest/job/native-index models fail closed on
  required fields, identity, versions, phases, canonical index configuration,
  source/column/ordinal, and non-ready IVF state. No disk metadata is altered.
- The independently checked missing-PK set is sorted/unique and excludes a
  rejected key with an earlier or later accepted source row. Unparseable PKs
  remain explicitly counted rather than inventing identifiers.

Source review and resolved findings:
- Fresh output reservation is O_EXCL, closes the raw descriptor before native
  locking, confirms identity, runs native pager Create/Commit, then opens sqlite
  with NoCreate. Resume never initializes an existing or missing destination.
  Namespace immutability/exclusive ownership remain documented preconditions.
- Source uses a held regular-file identity and bounded streaming SHA-256 check
  before output creation, and rechecks source identity/size/hash at completion.
- Reported early findings were fixed by the owner: an all-row dry-run seen set,
  hash decoding before length checking, empty index-method default ambiguity,
  and permissive completed/index-phase metadata invariants.
- Ascending dry-run/apply/verification are streaming in source rows. Apply uses
  bounded batches and PK provenance point lookups. Unordered dry-run has the
  explicit 65,536-key cap; rejection/missing-key reports are separately capped
  at 10,000 rejected rows. Native ANN construction has its own bounded quotas.
- Only typed deterministic row errors may be quarantined. Source-read errors
  have an isolated type that cannot become row errors or false EOF. Schema,
  context, resource and database failures stop. All importer data is bound;
  identifiers come from validated components, never a supplied SQL program.
- Commit errors return without retrying the uncertain batch. Ordinary resume
  reopens and exhaustively reconciles committed metadata/source/data first.
- Metadata is checked under native read snapshots. Completion is published only
  after a normal close/reopen exhaustive check, followed by another complete
  data/source/index reconciliation inside the writer-reserved publication
  transaction. Index identity checks use bounded read-only native catalog
  queries; extension-owned tables are never directly modified by the importer.
- Quarantine produces complete_with_rejections, never complete_verified.
  Verification failures do not retain a success status. Exact-distance and ANN
  recall fields explicitly remain not_run, separate from fidelity verification.
