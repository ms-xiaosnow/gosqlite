Findings corrected by lead, production edits not made by reviewer:
1. File.LockDB/DowngradeDBToShared returned ErrPoisoned without latching it.
   A partial downgrade could leave cached EXCLUSIVE true after physical SHARED
   conversion and make a later acquisition falsely succeed. lockResultLocked
   now latches closing=true before returning an ownership-poisoned result.
   checkLocked rejects further I/O, locking, and mapping before cached lock
   state or the private native descriptor can be used. Close remains possible.
2. The first SHM opener could retain a DMS writer hold after truncate or final
   writer-to-reader conversion failure without classifying ownership failure.
   nativeAttachDMS now tags those post-acquisition failures ErrPoisoned; errors
   before initial writer acquisition preserve their original classification.
3. Failed native SHM unlock now joins ErrPoisoned through the same latch.
   This protects direct managed-file/index callers as well as SharedSession's
   pre-existing poison-on-unlock-error path.

These failure branches were reviewed as source and modeled in memory only.
No native error, failed unmap, failed truncate, failed Sync, permission fault,
short write, disk-full, forced exit, kill, interrupted publication, corruption,
wrong-key, missing-selected-file, physical recovery, or namespace mutation
scenario was executed.

Ownership conclusions:
- Linux OFD locks are description-local. SHARED takes temporary PENDING read,
  then the SHARED range, then releases PENDING. Failed EXCLUSIVE releases
  temporary PENDING and retains SHARED; uncertain cleanup is poisoned.
- Portable SHM mode changes require explicit release. Linux's atomic backend
  conversion and range-unlock behavior remain separate low-level behavior.
- Original native mapping views remain owned independently of logical slices.
  File.Close attempts all view retirements before descriptor/DMS release; any
  retained view preserves the descriptor and all its locks for a later Close.
  Index.Close rejects further access while keeping its file for retry.
- SharedSession.Close keeps its main SHARED and WAL owners until index Close
  succeeds, preventing a compatible exclusive opener from removing live SHM.
- OpenSharedSession's failed-open cleanup likewise retains those owners after
  an index-retirement failure, but returns no session to the caller. This is an
  explicit fail-closed resource-leak/lifecycle gate: the registry retains the
  files, but no public Close retry for that failed-open group exists. Normal
  explicit Close retryability must not be described as universal recovery.
  A future bounded, synchronous pending-retirement group registry could provide
  explicit ordered retries without evicting live locks or background cleanup.
- WAL replacement requires distinct leases, a DB EXCLUSIVE owner, WAL roles,
  replaceable old/candidate leases, canonical related paths, and identity checks
  before native rename. Shared WAL opens opt out. Pager still orders candidate
  Sync, namespace publication, directory Sync, snapshot adoption, old close.
  Replacement itself was statically reviewed only; no replacement test ran.
- Recovery source remains internal, unsupported by ordinary public opens, and
  was only read. Manual recovery/namespace tests were never executed.
