Findings reported directly to owner and parent
---------------------------------------------
D1. FIXED: Darwin directory enumeration bypassed physical-resource ownership.
The original managedFile.ReadDir called os.File.ReadDir. Pinned Go 1.27.2
os/dir_darwin.go invokes internal/poll.FD.OpenDir, which duplicates the directory
handle for fdopendir; setup failure discards syscall.Close(fd2)'s result.
dirInfo.close also discards closedir errors. This hidden handle never reserved
shared registry capacity and had no terminal-close record. x/sys Getdirentries
was not a safe substitute: it opens another descriptor through Openat and
closes through fdopendir/closedir, also discarding some close results.
This was a source-proven resource-representation/boundedness gap, not observed
regular-database lock loss; the hidden alias is a directory descriptor.

Final fix inspected: directory_darwin.go invokes exported unix.Syscall6 with
SYS_GETDIRENTRIES64 on the already managed directory descriptor. No hidden open,
dup, close, libc DIR object, private linkname or fallback exists. The stream owns
one 64 KiB buffer, returns at most 64 names per call, and serializes with its
lease mutex. ABI assertions cover the Dirent field offsets; the bounded parser
uses explicit little-endian fields and consumes only returned bytes, excluding
the kernel's possible trailing flags word. It validates extent, name length,
termination and separators, skips dot/zero-inode records, and has no lazy Info
open. The exact trap ABI was checked against pinned Go/x/sys assembly and Apple
source. Direct-kernel ABI/native-version compatibility still requires native
validation and is explicitly marked compile-only in the platform document.

D2. FIXED: requested ASCII root restriction did not prevent Unicode alias
retention undercount. Apple's APFS documentation states that names preserve
spelling while lookup is normalization-insensitive; the Unicode Kelvin sign
canonically decomposes to ASCII K. An intact imported family preserving such a
Unicode prefix could be opened through an allowed ASCII root, while ASCII-only
prefix classification silently omitted its retained entries. No hostile active
rename/race is needed to describe this state. No such native fixture was run.

Final fix inspected: darwinFamilyEntry rejects every non-ASCII enumerated name
before family classification, including unrelated Unicode siblings. Portable
memory tests cover Kelvin-sign aliases, retained members, unrelated Unicode,
ordinary ASCII case aliases and unrelated ASCII names. The document now requires
a dedicated ASCII-entry directory while allowing Unicode in its parent path.
This is deliberately restrictive; full Apple Unicode equivalence remains an
implementation gap. Requested target basenames are checked before provider/
stable-lock acquisition, while the additional entry restriction is checked
when inventory runs. The final wording makes these timings distinct.

Ownership and protocol audit
----------------------------
1. Admission and identity: both nativeOpen and encryptedDarwinOpenHeld hold the
   same darwinfile.Process mutex across Admit, native open, fstat and Register.
   Descriptor-free lstat/fstatat hints allow pre-open per-inode refusal. Actual
   identity is the full Darwin (int32 device, uint64 inode) pair from fstat.
   Register precedes all validation-failure retirement. No raw handle escapes
   the encrypted managed lease. Raw handles whose identity cannot be obtained
   are quarantined before any os.File finalizer exists.
2. Shared bounds: the registry charges both domains, max 256 per inode and
   16,384 total. An unknown/raced alias can produce one represented overflow
   record; the global overflow blocks subsequent physical opens until drained.
   There is no eviction or close-to-make-room beneath live locks. The single
   gate holds the admission reservation continuously through registration.
3. Process fcntl lifetime: encstore and VFS publish their successful-lock marker
   while still under the gate used for the native lock call. Physical retirement
   requires neither domain to hold process locks for that inode. Deferred
   descriptors strongly retain the actual os.File through bound close callbacks.
   Last successful releases trigger draining. The VFS changes forward physical
   lifetime state; its separate SQLite range/DMS protocol remains intact.
4. Logical encrypted locks: processByteLocks separates each lease's three exact
   holds from aggregate kernel modes. Same-mode operations are idempotent;
   local conflicts return BUSY before native calls; multiple readers share one
   process read lock. Successful F_SETLK alone updates the aggregate ledger.
   Shared/exclusive conversion makes one native request with no unlock gap.
   Acquisition BUSY preserves old ownership; unexpected errors poison it.
   Ordered cleanup releases capture, writer, then lifecycle and retains every
   not-successfully-released hold when cleanup is partial.
5. Close uncertainty: attempted is set before native close. Known close errors
   retain a charged tombstone and poison the inode. Unknown close errors retain
   a charged quarantine entry and block physical opens globally. Neither path
   retries the numeric handle. Parent hook errors/panics cannot resurrect a
   consumed handle. Failed unlocks remain represented for ordered retry, distinct
   from the terminal native-close rule. Parent-child bookkeeping never takes a
   per-file mutex from the common lifecycle gate.
6. Reuse and parent pins: only idle, never-attempted, unpoisoned regular records
   are reused with matching access and parent identity. A fresh logical lease
   is created; old public Close cannot retire the new lease. Sequential position
   is reset. Pin transfer charges the new parent before releasing the previous
   one. Logical directory Close is permanent, but live children retain its raw
   descriptor for private relative identity checks. Unknown/failed child close
   does not release its parent pin.
7. Namespace: relative member names reject empty/dot/dot-dot, separator/NUL and
   excessive component lengths; only the explicit enumeration '.' is allowed.
   Openat uses O_NOFOLLOW/O_CLOEXEC/O_NONBLOCK and rejects truncating dispositions.
   Inspect verifies regular single-link files or directories plus MNT_LOCAL.
   Stable checks compare held and named identities, size/mtime evidence and the
   named original parent. Darwin Lstat/EvalSymlinks/SameFile are descriptor-free
   in the inspected pinned Go sources. Trusted cooperative hierarchy remains
   required; these checks are not a hostile namespace-race proof.
8. Publication and old leases: candidate and destination remain relative to the
   retained parent. Initial publication is native RENAME_EXCL; replacement is
   Renameat, followed by destination inode/type/link checks. No check-then-rename,
   link/unlink or copy/delete fallback was introduced. Common publication still
   owns its capture/writer/lifecycle protocol, candidate Sync, directory Sync,
   authentication, uncertainty marking, adoption and old-selection retirement.
   Existing formats, constants, content commitments and archive behavior were
   not changed by the Darwin slice.
