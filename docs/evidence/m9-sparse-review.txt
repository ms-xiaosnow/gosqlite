Independent review findings
1. Found by source review: SQL sparse score scratch was checked alone before
   candidate/query decoding; only after fetch did materializeVector combine
   that scratch with previously retained heap rows. Thus the logical combined
   memory budget could be rejected after decoding had already allocated.
2. Production owner fixed plan_vector.go/plan_sparse.go: materializer publishes
   retained-row-only bytes before each fetch; sparse score checks remaining
   MaxSortBytes with checked subtraction before either sparse decode. Existing
   post-fetch accounting still reserves scratch plus projection/retained rows.
3. TestSparseReviewCombinedScratchPreflightBeforeDecoding proves the fix with
   valid maximum support (16000 entries, dimension 1e9). Standalone scratch
   fits but retained+scratch exceeds budget: ErrMemoryLimit, no prepared state,
   no charged support and ZERO measured scoring allocations. Exact remaining
   scratch boundary succeeds and charges 16000, independent of dimension.
4. Initial measurement included one caller-side []byte-to-interface box per
   call. The harness now boxes caller input before AllocsPerRun, so it measures
   scoring allocations only. This was a test-harness issue, not an additional
   production defect. The final repeated CGO0 and race gates passed.

Verified behavior
- Exact independently assembled GSS v1 bytes: 16-byte header, version/format/
  endianness/flags, 1e9 dimension, nnz and zero-based interleaved index/float32
  bits. Text sorting/zero removal, duplicate explicit zeros vs retained-index
  uniqueness, zero-index/out-of-bounds-zero rejection, strict binary rejection
  of signed zero/nonfinite/unsorted/duplicate/out-of-range/length/count cases,
  smallest binary32 subnormal, empty support distinct from NULL/invalid object.
- Nullable scanner preserves state on failure and owns successful source data;
  source-buffer/accessor mutation cannot affect immutable values. Explicit
  billion-dimensional dense conversion fails with ErrLimit before allocation.
- All numerical functions accept sparse identity through unary +, coalesce,
  ifnull and nullif. Every dense/half/bit pairing in either argument order and
  mixed known coalesce/ifnull identity rejects. Closed constructor/conversion
  source signatures, closed GSS/GSV/GSH/GSB metric dispatch, dense behavior for
  two untyped strings and explicit dense/sparse conversions are checked.
- Arithmetic cancellation at maximum 16000 support is deterministic: the
  fourth context check aborts each of four metrics and norm with zero result;
  uncanceled maximum support uses <=66 checks rather than dimension-sized
  traversal. Empty dimension-1e9 supports require no dense allocation/work.
- Memory-only external TEXT/default/alias models preserve actual storage class
  and sparse expression identity. Numeric-affinity short-record defaults reject
  when interpreted; unrelated false predicates may filter them first. Typed
  invalid candidates still reject with a NULL query; NULL candidates suppress
  malformed query decoding, matching full-sort/heap behavior.
- Candidate budgets count NULL and filtered source rows. Conservative explicit
  zero-entry support accounting uses query=3 plus two merges of (3+2)=13;
  budgets 1,3,7,8,12 reject without published partial ranking and 13 succeeds.
  Entry-count and byte preflight precede malformed text parsing. Both heap and
  full sorter reject insufficient retained memory. Dense/bit work counters stay
  zero for sparse ranking.
- Independent exact reference embeds only THREE coordinates at distant indices
  0/499999999/999999999; no production metric/heap/reference decoder is used.
  Native top-k, SQL heap and full-sort match for two queries, all four metrics,
  both argument orders, filtered/unfiltered sets, NULLs, signed MinInt64 and
  MaxInt64 ties, ordinal ordering, LIMIT/OFFSET and empty windows. Native NULL
  exclusion and SQL NULL-first order are independently checked.
- Native default storage matches independent exact GSS bytes. Failed typed
  UPDATE leaves earlier transaction writes intact; normal outer rollback
  removes them. Sparse subvector/binary_quantize explicitly return unsupported;
  billion-dimensional dense conversion and dense/half/bit physical-column
  misuse reject. HNSW/IVFFlat creation on sparse columns rejects.
- Native option hard caps/partial invalid options, result caps, closed metric
  strings, typed Valuer entry/memory preflight, typed nil pointers, NULLs,
  zero-support tiny-memory success, and filtered/NULL candidate quotas checked.
  Native zero-limit cosine validates zero norm; a later zero-norm candidate
  returns no partial result. WHERE may exclude that candidate before scoring.
- Native/SQL midscan cancellation, custom Valuer cancellation/errors, and all
  error zero-results verified. An ordinary second writer and checkpoint after
  canceled searches verify released readers. Rows.Close releases decoded/bound
  sparse state and retains plan/stat diagnostics.
