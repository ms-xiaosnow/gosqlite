Findings raised during review and dispositions
1. The initial CleanupOwners collector returned early for repeated *File owners
   before inspecting later wrapper causes. Joined wrappers could hide distinct
   child obligations; merely moving child traversal first could still emit a
   shared parent before a later-discovered child. Corrected in cleanup.go lines 47-128:
   collect all identities and dependency edges first, then emit child-first.
   Shared identities deduplicate only the resource, not independent wrapper
   causes. An inconsistent dependency cycle returns a leading terminal barrier
   and retains every concrete owner. Repeated/transitive-child laws and the
   independent 64 DAG subsets x two tree orders all pass.
2. Nested constructors may return nil after acquiring a resource. File.Close now
   error-carries unresolved managed owners, and failed Open metadata/native
   probes carry terminal obligations where no safe managed retry exists. The
   existing walindex.Open failed-open defer preserves File.Close's typed error;
   walindex/index.go requires no source edit for this adoption route. Pager
   failedOpen collects all those obligations before closing index/WAL/main.
   Specifically inspected Darwin nativeOpen pre-File Seek/Retire and Fstat/
   Quarantine paths: unmanagedOpenError conservatively represents poisoned
   rejection as terminal when no precise lower obligation is available.
3. Windows nativeMap failed-view cleanup and nativeUnmap previously retried an
   uncertain mapping-object HANDLE. This was a real source blocker in the base
   tree, not native-failure evidence. The separate three-path correction above
   latches first close uncertainty, never reissues that raw close, preserves
   view/owner/protectors, and permits only represented view retry after known
   object-handle retirement. Standalone source/memory/race/Windows compilation
   review passed; see its separate report for exact rationale and commands.
4. The original public helper selected only the first group from errors.As, so
   an already-completed first group could hide later pending groups. The lead
   requested all-group semantics. The final helper discovers every distinct
   reachable group before touching owners, attempts every discovered group,
   and joins only current failures. Duplicate/completed-first/multiple-pending
   and repeated-current-output laws pass.
5. Darwin nativeClose -> darwinRelease -> darwinPoison could repeatedly call
   darwinfile.Registry.Poison, which recursively retained previous error history.
   The lead corrected Registry.Poison lines 75-87: retain the first poison once, return
   a fresh first+current join for later operations without retaining it. The
   original stored graph remains identical across 10,000 modeled calls; original
   and current causes remain discoverable. Full registry memory and race laws
   pass. One-time Record close/hook errors remain bounded by represented records.

Verified source invariants
- OpenSharedSession reserves one of 64 groups after context/options checks and
  before filepath resolution/native probes/acquisition. Success transfers every
  acquired main/WAL/index owner and removes exactly its reservation without
  closing them. In-flight plus pending groups are bounded; live successful
  sessions are not counted. Admission never evicts or sweeps another group.
- The registry strongly retains group/managed-owner reachability independently
  of the caller keeping a returned session or error. There is no finalizer,
  eviction, background goroutine, raw-handle API, or implicit retry loop.
- Nested obligations retire child-first. Index views/mapping objects and DMS
  precede WAL; WAL precedes main. An error stops that group's protective tail.
  Only successful managed retirement clears a slot. Consumed Linux os.File
  closes cannot be retried raw; corrected Windows terminal states remain held.
- Each group mutex serializes state and retries. The registry mutex spans only
  admission/removal, never managed cleanup. No two group locks are held together.
  An independent request can progress while a fake owner in another group is
  blocked. Existing backend-specific lifecycle locks are unchanged by this layer.
- Original errors and first opening/cleanup causes stay immutable. Each retry
  constructs a bounded original-plus-current result; completed groups become
  no-ops. Common wrappers retain errors.Is/As causes and package classification.
  Pending opening errors also match ErrPoisoned and public CodeIOErr, even when
  the initial opening cause was BUSY. Capacity refusal maps to ErrMemoryLimit/
  CodeNoMem. The pending sentinel alone is not itself a poisoned opening error.

Final API semantics and limits
- Nil and ordinary small non-group error trees are no-ops. Ordinary %w wrapping
  and errors.Join are traversed; each unique group is attempted once per call.
- Successful nil means every discovered group finished its managed retirement;
  it does not mean a database opened, original causes vanished, or future opening
  is guaranteed. Historical pending errors continue to match their sentinels.
- Discovery is capped at 4096 nodes and completes before cleanup. Oversized and
  cyclic wrapper inputs return explicit ErrLimit/public ErrMemoryLimit without
  touching any owner. This refusal deliberately omits the unsafe original chain;
  retain original opening errors and retry smaller trees. It is the documented
  exception to a reusable pending-error return. Recognized group tokens are
  leaves, so retry histories are not repeatedly expanded.
- A failed group does not suppress attempts on independent groups. Current
  pending failures retain their original causes and may be joined/retried again.
- Terminal obligations can occupy capacity/protectors for process lifetime.
  Pre-existing/global poison may conservatively retain an otherwise empty group.
  The policy favors represented ownership over availability.

package vfs

import (
 "errors"
 "testing"
)

// Independent exhaustive memory law: all 64 acyclic dependency subsets among
// four descriptor-free owners, each with forward and reversed error-tree order.
// File.Close on these empty owners returns before any native operation.
func TestIndependentCleanupAllDAGOrders(t *testing.T) {
 for mask := 0; mask < 64; mask++ {
  for _, reverse := range []bool{false, true} {
   files := []*File{{}, {}, {}, {}}
   var branches []error
   cause := errors.New("memory cause")
   for _, f := range files { branches = append(branches, retainedFileCleanup(f, cause)) }
   var edges [][2]int
   bit := 0
   for parent := 1; parent < 4; parent++ {
    for child := 0; child < parent; child++ {
     if mask & (1 << bit) != 0 {
      branches = append(branches, retainedFileCleanup(files[parent], retainedFileCleanup(files[child], cause)))
      edges = append(edges, [2]int{parent, child})
     }
     bit++
    }
   }
   if reverse { for i, j := 0, len(branches)-1; i < j; i, j = i+1, j-1 { branches[i], branches[j] = branches[j], branches[i] } }
   joined := errors.Join(branches...)
   // Repeated identical subtrees must not multiply returned owner identities.
   owners := CleanupOwners(errors.Join(joined, joined))
   if len(owners) != len(files) { t.Fatalf("mask=%d reverse=%t count=%d", mask, reverse, len(owners)) }
   positions := map[*File]int{}
   for i, o := range owners {
    f := o.(*cleanupError).file
    if _, ok := positions[f]; ok { t.Fatal("repeated owner") }
    positions[f] = i
    if err := o.Close(); err != nil { t.Fatal(err) }
   }
   for _, edge := range edges {
    if positions[files[edge[1]]] >= positions[files[edge[0]]] { t.Fatalf("mask=%d reverse=%t parent retired before child %v", mask, reverse, edge) }
   }
  }
 }
}
