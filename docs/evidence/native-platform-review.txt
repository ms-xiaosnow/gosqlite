Darwin process-fcntl ownership:
- nativeOpen holds the lifecycle gate across raw open, fstat identity capture,
  node lookup, and descriptor registration. Registration precedes any normal
  validation rejection that can reach Close. Unknown-fstat descriptors remain
  raw integers in quarantine and never acquire an os.File finalizer.
- Rejected opens, probes, plain DB/WAL/SHM/journal files, and directory leases
  use the same managed ownership. A search found no raw os.Open/OpenFile/Create/
  ReadFile or exposed *os.File in the plain pager/WAL-index/SQLite production
  paths. The separate encrypted store remains behind its non-Darwin stub.
- File.mu precedes the registry gate. Registry operations do not acquire a
  sibling File.mu. Active descriptors are never drained; idle descriptors are
  reusable only by matching role/access. Their seek position is reset first.
- Per-inode logical holds are aggregated before process fcntl changes. Local
  exclusivity conflicts are rejected even though the kernel would coalesce
  process ownership. Successful syscalls alone update the kernel ledger.
- Failed EXCLUSIVE acquisition preserves process SHARED and releases temporary
  PENDING. Downgrade replaces the shared range before releasing PENDING.
  Failed cleanup poisons the entire inode; ordinary operations on peers stop.
- Close releases only the retiring descriptor's logical holds, retains sibling
  aggregate holds, defers physical close while any aggregate hold remains,
  and drains idle descriptors under the same gate after locks are gone.
  Unknown-identity quarantine is drained only with no managed locks anywhere.
- First-local DMS ownership is explicit: an existing local shared aggregate
  bypasses F_GETLK/reset; the first opener alone follows query/exclusive/reset/
  shared conversion. A lost exclusive-initializer race remains BUSY.
- This coverage cannot intercept unmanaged same-inode closes in the same
  process. That limitation is explicitly declared, not assumed away.

Windows exact ownership and native policy:
- FILE_ID_INFO retains the full 128-bit ID and volume identity. Native parent
  and final-file inspections precede common validation. ABI size/offset
  assertions cover the reviewed amd64 SYSTEM_INFO and metadata structures.
- Local fixed NTFS/path/reparse restrictions and compatible metadata probes
  are present. Read/write sharing is distinct from delete sharing, which is
  limited to explicitly replaceable exclusive-session WAL participants.
- Each successful LockFileEx acquisition has a fixed interval/mode record.
  Same-mode repeats do not stack. SHM native operations use exact individual
  bytes, so logical subrange/union unlock does not violate UnlockFileEx's
  original-acquisition requirement. Partial acquisitions unwind only new holds
  in reverse order; conversion is rejected before calls.
- Direct SHARED-to-EXCLUSIVE acquires PENDING independently of RESERVED.
  After dropping SHARED, failed exclusive acquisition restores SHARED before
  dropping PENDING. An unsuccessful restoration/unlock poisons ownership.
  Only ERROR_LOCK_VIOLATION is ordinary contention. RESERVED probes use a
  transient shared-byte acquisition, also valid on read-only handles.
- First-local DMS reset/attachment is serialized with final detachment. Later
  connections retain independent OS shared DMS locks without another reset.
  There is no arbitrary truncation-error header-erasure fallback.
- Close retires recorded mappings/retained mapping objects before DMS/file
  retirement. Successful partial cleanup clears only its own record. A raw
  os.File.Close error is a terminal uncertain tombstone, never a blind retry.

Mappings and common lifetime:
- mappingSpan conserves the logical end: aligned base + native length equals
  requested offset + requested length, with checked int64/int arithmetic.
  A 32 KiB first block is not enlarged to 64 KiB merely for allocation alignment.
- Windows uses GetSystemInfo allocation granularity, zero mapping maximum
  (existing file size), a retained original view base, and a separate mapping
  object handle. Overlapping later views do not relocate earlier live views.
- Closing the mapping HANDLE before UnmapViewOfFile is supported by Microsoft's
  lifetime contract. The exposed slice remains live if either retirement stage
  fails, and the protecting file/DMS owner remains retained until retirement.
- Native poison is checked before portable cached-success fast paths. Common
  Close retires every mapping before calling nativeClose and retains owners on
  unresolved retirement. Nil raw owners reject stale cached lock bits first.
- SharedSession cleanup retains DB/WAL protection if index retirement remains
  unresolved. The already documented failed-OpenSharedSession limitation still
  exists: retained protection may have no reachable public session for retry.
  This review does not establish bounded or universally retryable cleanup.

Publication and synchronization (SOURCE ONLY; no replacement executed):
- ReplaceWAL validates distinct owners, exclusive DB ownership, roles,
  replacement permission, same-directory candidate naming, and identities.
  Windows MoveFileEx uses REPLACE_EXISTING|WRITE_THROUGH with no COPY_ALLOWED,
  copy/delete, or delete/rename fallback. Native uncertain outcomes and failed
  post-replacement identity verification poison all three common participants.
- The pager adopts the candidate only after successful replacement and poisons
  failed normalization. Candidate Sync precedes replacement; the declared
  directory policy is applied afterward. No retryable-publication claim is
  inferred from an uncertain result.
- Darwin explicitly supplies fsync, not F_FULLFSYNC/device-cache acceptance.
  Windows regular files use FlushFileBuffers; its directory hook intentionally
  supplies no namespace barrier. MOVEFILE_WRITE_THROUGH is not treated as proof
  of interruption safety. These limits agree with ADR 0015 and Windows docs.
- Linux native_linux.go is byte-identical to HEAD. The default ownership hooks
  are no-ops for Linux; OFD syscall semantics were not replaced with process
  locking. Unsupported targets retain the fail-closed stub.
