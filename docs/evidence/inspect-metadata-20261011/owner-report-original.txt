## Implementation

`DB.Inspect(ctx, InspectOptions)` returns one snapshot's Header, Schema and
optional ExtensionIndexes. It borrows an active transaction reader after the
normal check/ensureSnapshotLocked path; otherwise it owns exactly one openReader.
Owned-reader Close errors are joined and clear the result. Context and active
transaction state are checked again before success. Info observes a successful
inspection's fresh header. Cleanup-error behavior was source-reviewed, not fault
injected in this scope.

The separate decoder only walks sqlite_schema and __gosqlite_ext_catalog. It
checks the exact base schema envelope and optional whole ANN envelope, schema
name/root uniqueness, known owned names, the 13-column catalog shape, integer
ranges, current storage version and positive representable method versions.
It does not call loadExtensions, loadExtensionsEntries, validateCatalog, Query,
Check, method lookup, Configure, Canonical or Keys. It never parses config/source
SQL or reads source/fields/postings/frequency/ANN data roots. Recognized logical
guard names do not imply those guards or an index are usable.

Public metadata is ID, name, source_table, method, method_version,
storage_version, config and generation. Config is an opaque UTF-8 string,
including legitimate non-JSON whole-v1. Newly exposed text is checked before
JSON can silently replace invalid UTF-8. The invalid-UTF8 rejection branch was
source-reviewed only; no malformed database fixture was introduced.

At most 1024 records are retained. Conservative MaxSortBytes charges cover
metadata maps/names/output retention and record allocations. NewBudgetCursor
reserves before overflow/decode. Schema, B-tree and payload limits apply
independently; there is no total-heap/RSS guarantee.

The CLI keeps exactly the required OpenContext(ctx,args[1],ReadOnly:true) call.
Both modes use the one Inspect result before output. Default JSON bytes and
uppercase nested header/schema fields remain unchanged. --extensions adds
extension_indexes, including [] for an empty catalog. An output-writer failure
can still leave partial output, as before; metadata preparation errors do not.
