## Static audit

### Snapshot, context, result and ownership

`sqlite/inspect.go:51-117` takes the connection mutex before selecting the reader.
An active transaction follows its existing `check` / `ensureSnapshotLocked`
path and lends its reader; no reader-close callback is installed in that case.
A nontransaction call obtains one `openReader` result and installs precisely one
close callback. Header, schema and optional catalog are all read through that
same reader. The connection mutex prevents concurrent transaction replacement
or connection retirement while the deferred checks run.

The owned close executes before mutex unlock. `wrapCleanup` joins a cleanup
error with an earlier inspection error while preserving error discovery; caller
context and active-transaction context are rechecked before success. Any such
error clears the entire named `InspectResult`, including errors that occur
only during deferred cleanup. `Info` receives the successful snapshot header.
Initial nil/canceled contexts and closed handles return zero results. Borrowed
transaction lifetime is preserved; its existing first-access logic may pin its
snapshot, as expected for a metadata read.

Cancellation reaches schema/cursor page reads and iteration. Bounded schema
copying and schema-root identity scans have final context checks rather than a
hard real-time cancellation-latency guarantee. Reader-acquisition internals and
cleanup/error classifications were not changed. The cursor's deferred Close is
currently infallible and only retires cursor buffers; it does not own the reader.

### Catalog-only behavior and schema envelope

The inspect-specific path calls `btree.ReadSchema` and, only when requested,
one `NewBudgetCursor` over the extension catalog root. Static examination finds
no operational extension loader, registry lookup, Configure, Canonical, Keys,
source SQL parser, integrity checker, or source/fields/postings/frequency/ANN
root traversal. `extensionSchemas`, `annSchemas`, `extensionReserved` and
`extensionGuardName` used here are pure schema/name helpers.

The decoder checks ASCII-folded schema-name uniqueness; when owned objects
exist, it checks positive-root uniqueness and byte-exact current base schema
identities. Any member of the optional ANN schema family requires that entire
schema envelope. Known generated guard names are recognized without declaring
their SQL/type or the index usable. Unexpected owned-prefix objects fail closed.

Catalog row IDs must be positive and rows must contain exactly 13 fields with
a NULL rowid alias. Text types and integer ranges are checked. Storage version
must equal the current envelope version. Method version must be positive and
representable as int; unknown positive method versions can be reported without
requiring a registered implementation. This is intentional metadata behavior.
Newly returned text fields must be valid UTF-8, avoiding lossy JSON replacement.
Config is returned unchanged as an opaque string, not parsed or embedded JSON.
Source/config hashes, dirty state, source counts, generation correctness and ANN
semantics are not verified or presented as validity evidence.

### Quota and allocation boundary

`sqlite/inspect.go:120-197` reserves a fixed allowance before maps, charges schema
map/folded-name entries and positive-root maps, and retains every catalog-record
reservation to completion. At most 1,024 successfully retained records are
allowed. The next record is refused before payload assembly or decode.

The existing B-tree cursor calls `beforeRecord(item.payload)` before `payload`
overflow allocation and `record.Decode`, including local payloads. Its existing
64 MiB payload cap makes the `128*n + 2048` reservation arithmetic safe in int64.
The conservative factor covers the payload, variable-column decoder growth,
retained strings, result growth and per-record name/guard maps even before row
shape has been established. Subtraction-based reservation prevents budget
addition overflow. No reservation is released while retained results remain.

This is an accounting bound on the documented inspection metadata/decode
allocations, not a measured allocator/total-heap/RSS bound. Schema materialization,
B-tree page/visited bookkeeping and page-cache allocations remain governed by
their existing independent limits. The docs explicitly preserve that boundary.
Default inspection does not enter this optional catalog budget path.

### CLI and compatibility

The production delta outside the new API is confined to inspect handling and
usage text in `cmd/gosqlite/main.go`. The exact existing
`sqlite.OpenContext(ctx, args[1], sqlite.Options{ReadOnly: true})` call remains,
and the unchanged AST assertion still passes. `--extensions` is opt-in before
the database argument. Both modes prepare one complete Inspect result before
encoding. The default format string, field names, order, uppercase nested
header/schema names and newline are unchanged. The optional field is an array,
including `[]` when empty. Opaque non-JSON custom config is JSON string-escaped.
The existing CLI Close error is joined. Output writer failures can still yield
partial JSON writes; documentation states this, and no stronger output-atomicity
claim is made.
