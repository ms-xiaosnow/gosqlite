Finding and resolution
- Found: loading an existing official schema revalidated HALFVEC defaults using
  native write rules. ALTER ... ADD h HALFVEC(1) DEFAULT '1' correctly failed
  typed reads, but also prevented explicit UPDATE h='[1.0001]' of that value.
- Production owner fixed sqlite/write_schema.go: existing-catalog HALFVEC
  defaults retain expression validation but defer typed validation until value
  use. Native CREATE still validates before schema publication. The numeric
  default regression and the complete four-test oracle selection passed 3 times.
- Review-harness corrections: aggregate count is outside the current SQL subset;
  result aliases are exercised in supported WHERE/ORDER contexts rather than
  sibling projection expressions; successful materialize already releases source.
  These initial test failures were not production defects.
