## Benchmark methodology and cleanup review

- Native `sqlite.Open`, ordinary source insert transaction, and `CreateGramsIndex` create a real persisted SQLite-format database and grams shadow B-trees. No external SQL oracle or mock index is used.
- It measures a **joint** 1/2/3-gram index containing both LIKE and MATCH namespaces. Build time includes native ordinary commit. The file-byte increase measures catalog, postings, frequencies, B-tree structure and slack. It must not be described as independent per-length build time/space, live payload bytes, peak disk usage, or RSS.
- Timed queries require exact gram length 1/2/3 with actual posting reads/candidates/fetches and fewer source fetches than the reference. Reference plans must say SCAN / NOT INDEXED requested, fetch every source row and read no postings. Full ordered IDs must match. `%` and `%common%` remain separate explained fallback controls.
- Plan/counter inspection confirms these are actual native logical operations. They are not physical page-I/O counters. `FrequencyLookups` includes planning probes; returned covering posting records feed `PostingKeysRead`; actual source evaluation increments `BaseRowFetches`.
- Every query records raw times, plans, counters and ordered-result hash. P50/P95 are nearest-rank empirical quantiles; mean, sample standard deviation, min/max and N are descriptive. Repeated independent database builds share one process/host/corpus, and the report explicitly declines an inferential CI. Small-N P95 may be the maximum. No universal speedup or statistically significant performance claim is supported.
- Cold-connection mode opens a fresh read-only connection for each query; warm-process mode performs a complete unmeasured workload first on its reopened connection. Neither flushes the OS cache. Timings include parse/planning/execution/result consumption/Rows.Close, excluding connection Open/Close. Query pair order and cache profile order alternate. Documentation correctly discloses these boundaries.
- Fixed seed, corpus digest, page size, actual Go/platform/GOMAXPROCS/build settings/modules and operator-supplied source/environment identities are recorded. Environment/source labels are explicitly not automatic attestation. The measured shared container cannot satisfy controlled fixed-hardware release qualification by itself.
- Rows, queries, repeats, page sizes and dirty-page budgets are bounded. Generated text length is bounded; retained raw observation count is bounded. No native quota is silently bypassed by shrinking the corpus. Successful directories are removed after all native closes complete; any run error retains its trial directory in failed JSON.
- `runTrial` installs retention cleanup before the DB-close defer, so LIFO closes the DB first and joins any close error into the named return before deciding whether removal is safe. Fresh-query and warm-connection closes are also propagated. Explicit pre-query close failures preserve their error even if the deferred retry later succeeds. A commit/rollback/native error is propagated and prevents directory removal. This retention behavior was source-reviewed; native failure injection was deliberately not performed.
- Normal test fixtures continue to use the baseline test helper; no physical close/error behavior is asserted by these ordinary tests. Existing fixture failure paths are not a new native-failure qualification.
