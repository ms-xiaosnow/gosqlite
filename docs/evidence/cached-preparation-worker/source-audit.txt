Native production review:
- Cache is a DB mutex-owned pointer, no global map or cross-connection sharing. Query/Schema/write/close hooks run under the existing lock. Rows own no cache reference.
- Cache entries are independent string copies and copied column arrays/maps. Zero roots, nil defaults/extensions/indexes, no reader or pager handle. Mutating statement ASTs during shared preparation cannot mutate schema entries.
- Metadata budget includes fixed allocation, per-table and per-column allowance and copied string bytes. Empty-cache fixed quota bug found independently was fixed before final freeze. Optional read catalog parsing is charged separately before parsing and retains parser bounds.
- Normal successful snapshot first invalidates a stale cookie and always rebuilds its current writable catalog. Existing ownership validation and storage.Statement execute before real DML data access. A cache cannot return success from snapshot admission or skip row/index validation.
- Only pure ordinary pager/VFS BUSY leaves in the native error tree enable cached classification. Any other leaf leaves native admission error and non-started outcome unchanged. This was unit-tested without any native failure injection.
- Shared prepareInsert/prepareUpdate/prepareDelete preserve the original target/bind/arity checks, now with context checks at expression nodes. Parameters still bind before DB lock/snapshot; runtime expressions never run from the cache.
- mutationOutcome.started feeds the existing completion routine only. Changes resets on classified executed BUSY; total/last-rowid untouched. Source-row insertion/ABORT accounting and automatic-vs-explicit completion remain in their original code positions.
- Successful CREATE updates statement-local catalog only. Cache snapshots remain immutable. Schema cookie guards, DDL full rollback, DDL-discarding savepoint rollback, failed automatic DDL commit and Close disposal were reviewed and tested.
- Session/extension/unsupported-catalog cache exclusions preserve their old early-admission behavior. Constant SELECT and SQL sqlite_schema projection do not populate this optional cache; DB constants still open a reader, Tx constants stay lazy.
