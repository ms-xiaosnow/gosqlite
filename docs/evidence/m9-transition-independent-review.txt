Finding 1 — corrected: correlated verification name capture
---------------------------------------------------------
The old float32 fidelity SELECT used unqualified source/shadow column names in
the second unnest table function, after the first function's a(x,n) alias.
PostgreSQL table functions implicitly see preceding FROM items. A valid source
or shadow named x/n could resolve to that local scalar/ordinality rather than
the outer table value, producing an invalid cast/lateral reference. Quoting
identifiers alone did not prevent this semantic identity capture.

Correction: bind the outer table AS src and qualify every source/shadow use in
that exhaustive comparison SELECT. The norm SELECT was already qualified and
was not changed. Regression covers retained-array and typed-shadow approaches
with x, n, a, b and an embedded quote in the column name.

Official basis: PostgreSQL table expressions, especially implicit LATERAL for
table-function arguments and table/column aliases:
https://www.postgresql.org/docs/18/queries-table-expressions.html

Finding 2 — corrected: selected inheritance parent was eligible
------------------------------------------------------------
The inspector rejects a selected relation whose own Parents is nonempty, but
that does not identify a selected parent with an inventoried child. A synthetic
child with Parents=[30000] still yielded review_required for parent 30000.
PostgreSQL queries/updates/column ALTER normally recurse into descendants, and
a parent's PK does not enforce uniqueness over its inheritance children.
This contradicts the generator's one-heap/keyset subset and can affect rows
outside the intended physical heap and defeat keyset uniqueness assumptions.

Correction: GenerateTransition scans supplied relation parent links and emits
source_inheritance_unsupported when any inventoried relation directly inherits
from the selected source. All proposed phase bodies are then withheld. It does
not emit ONLY or pretend to implement inheritance migration. Existing selected
child/partition-parent rejection remains in the inspector. Fresh complete
inventory/quiescence gates still apply: this guard cannot prove the absence of
unreported children. No transitive traversal is needed to reject a hierarchy
whose complete inventory contains the selected source's direct child.

Official basis:
https://www.postgresql.org/docs/18/ddl-inherit.html
https://www.postgresql.org/docs/18/sql-altertable.html

Contract conclusions
--------------------
1. Approach distinction: retained REAL[] uses qualified vector(n) expression
   casts for indexes/queries without backfill. Typed copy creates one nullable
   shadow on the same table and preserves source arrays. Historical full-table
   typed copy, recreation of defaults/grants/constraints/dependencies, and table
   replacement are explicitly not implemented. No source rename/drop is emitted.

2. Extension/dependency scope: both pinned SQL sources define global hnsw;
   changing extension schema cannot provide coexistence. All inventoried old
   ANN indexes must have verified mappings on the selected column. Unplanned
   legacy indexes, incomplete required coverage and unhandled dependencies
   block phase bodies. Dependency definitions and corpus text remain JSON.
   Preflight walks transitive pg_depend object addresses and separately lists
   inheritance, triggers, constraints, policies and rewrite rules. Coverage
   claims are supplied evidence, not independently verified completeness;
   catalog/dependency fingerprint comparison remains an unresolved human gate.
   The baseline collector's direct-only inventory is not accepted as complete.

3. Safe SQL generation: names have a 63-byte UTF-8 bound, embedded quotes are
   doubled, control/line-separator names are rejected, and comparison literals
   use E-string escaping independent of standard_conforming_strings. Methods,
   opclasses/operators, types and numeric options come from closed mappings or
   bounded integers. No raw index/function/dependency definition is interpolated
   into SQL. Every physical line of phases 10..70 is commented, including
   BEGIN/COMMIT/ROLLBACK and read queries. Bare CR cannot escape that boundary.
   00-preflight.sql alone contains active SQL, with a READ ONLY REPEATABLE READ
   transaction, trusted pg_catalog path, timeouts and catalog/row diagnostics.

4. Capabilities: exact source embedding 0.3.6 and requested target vector 0.8.7
   are pinned. Existing vector installation and unknown requested/server
   versions block. Post-install queries expose version/schema, AM/type/cast/
   operator/function/opclass ownership/signatures; they do not automatically
   approve actual capability or installation availability. Target HNSW/IVF
   options are explicit and bounded. Source option errors cannot be waived by
   target choices. Manhattan maps to dense <+>/vector_l1_ops, never bit Hamming
   or unsupported IVF L1. Dense storage/index limits remain distinct.

5. Transaction boundaries: single mode retains one connection/transaction from
   extension transition through ordinary indexes/validation and gated cutover
   commit. Concurrent builds are rejected in single mode; in multi mode they
   carry outside-explicit-transaction metadata and no BEGIN/COMMIT wrapper.
   Invalid concurrent-index remnants require inspection and separately reviewed
   retry. The generator never runs these operations or uses IF NOT EXISTS to
   adopt an object with unverified identity.

6. Cursor/state: typed multi-batch state is newly created, plan-bound and locked
   before ordered key selection. Initial SQL NULL cursor includes MinInt64;
   source SQL NULL arrays still produce changed/RETURNING rows. Progress uses
   those returned rows in the same statement/transaction and compares prior
   cursor, count and batch number. No OFFSET, SKIP LOCKED, shadow-NULL progress
   predicate or synthetic minimum sentinel exists. Completion requires an empty
   batch and exact expected count. Missing progress/empty incomplete batch is
   explicitly a stop condition. Returned text is not proof of COMMIT.

7. State identity limitation: plan SHA binds all supplied canonical catalog
   facts and normalized choices, including batch size; artifact hashes bind
   the generated bytes separately. It is not a generator-version upgrade or
   state-adoption protocol. Reuse the original approved bundle; do not regenerate
   over in-progress state or treat matching data/options as permission to do so.

8. Write fencing: single mode takes ACCESS EXCLUSIVE on the selected source.
   Multi-mode row locks do not fence writers between commits. External write,
   DDL and PK-change quiescence is mandatory from validation through cutover,
   explicit in batch text and unresolved maintenance_window/fresh_catalog gates.
   Online dual-write or parallel scheduling is not implemented/certified.

9. Fidelity/NULL/zero: preflight diagnoses shape, lower bounds, dimension, NULL
   elements, nonfinite values, zero norm, counts and PK distinct/min/max. Full
   verification aligns NULLs and dimensions, compares float4send bytes per
   ordinality and uses an explicit 1e-6 absolute + 1e-6 relative norm tolerance.
   Source NULL remains target NULL. Inspector rejects cosine zero-norm source
   profiles. These checks do not establish legacy distance-bit equivalence:
   old float32 arithmetic differs from modern/local arithmetic. Exact/business
   baselines, actual plans and ANN recall remain separate unresolved checks;
   ANN/NULL membership and tie behavior must be tested under the deployed plan.

10. Rollback: only the still-open single transaction can be rolled back as one
    database transaction. Later ROLLBACK cannot reverse an earlier extension
    transition/index/backfill commit. Retained source data does not restore old
    functions/operators/ANN; after cutover it must be maintained/reconciled for
    source-reader rollback. Old-service restore needs available old binaries,
    backup/branch restore or reviewed reverse migration, and reconciliation of
    new vector-owned dependencies/global hnsw. No instant old-service rollback,
    cleanup, CASCADE or automatic reverse migration is claimed.
